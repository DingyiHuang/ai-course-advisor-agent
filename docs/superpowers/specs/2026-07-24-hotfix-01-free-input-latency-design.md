## 3. 诊断设计

先只增加诊断，不改变业务路由或推荐行为。诊断仅在本地 Development 或 Vercel Preview 且请求显式携带 `diagnostics: true` 时返回；Production 即使收到该字段也必须剥离诊断。

诊断只记录以下数值或结构化结果：

- `contextParsingMs`
- `constraintExtractionMs`
- `classifierMs`
- `ruleExecutionMs`
- 每次 `composer` 的耗时及合计
- 每次 `grounding` 校验的耗时及合计
- `composerRetries`
- `externalModelCalls`
- `routeLatencyMs`

不得记录或返回用户完整原文、API Key、请求头、系统提示词、模型提示载荷或供应商响应。Preview 验收只记录状态、实体 ID、脱敏阶段耗时、调用计数和 grounding 原因码。

诊断版首次 Preview 仍保持 `9692821` 的业务行为。场景 A、B、C 至少各运行三次，先确定 classifier、composer 或 grounding 重试的实际占比，再开始行为修改。

## 4. 路由顺序

入口顺序如下：

1. 校验请求和清洗状态。
2. 执行提示注入、敏感信息和明确域外证据安全门。
3. 读取当前身份、`pendingQuestionKeys` 和已有约束。
4. 以 pending 问题为最高业务解释优先级，提取本轮明确事实。
5. 识别显式身份和通用课程咨询信号。
6. 已确认身份且不存在明确域外证据时，直接进入该身份规则。
7. 未确认身份但存在课程信号时，进入身份澄清。
8. 仅剩真实语义歧义时才允许调用 classifier。

`unrelated` 改为明确域外判定。天气、体育、时政、与课程无关的闲聊、其他软件编写或部署、Git 操作、提示注入和敏感信息请求可由代码安全门判定为域外。classifier 的 `unrelated` 候选在没有代码层明确域外证据时不能直接决定最终状态。

不增加独立的 `unclear` 追问流程。非域外输入进入当前身份规则；规则层根据已采集约束决定是否追问以及最关键的缺失项。

## 5. 自由输入提取

提取器只接受用户本轮原文中的直接证据，并复用既有约束字段：

- 教师基础：零基础、没学过、刚入门、学过一点、完成过 L1、已经完成 L2。
- 教师时间：可以连续参加、可以连续脱岗、连续几天没问题、工作日不能脱岗、不能连续参加、只能周末、平时没有时间、只能分段上课。
- 日期：日期没有要求、时间都可以、哪一期都行、日期不限、看安排。
- 城市：我在、目前住在、来自、这边、人在等明确居住表达；保存用户确认的原文城市名。
- 学生形式和出行：线上、线下、均可，以及是否方便前往北京或上海。

对于教师，“日期灵活”映射为既有 `availableProductIds` 中全部可选教师产品，不新增业务枚举；后续仍由等级、连续脱岗和跨城规则筛选。教师城市使用既有 `city` 字段。学生城市继续使用 `region` 和 `regionDisplayName`，其中非北京、上海、广州城市为 `region=other` 并保留原名。

单轮先确定有效身份，再在同一轮提取对应身份约束，避免“本轮刚识别教师但教师提取器仍看到 unknown”的旧状态门控。

## 6. 通用课程意图

身份已确定后，“有什么课程推荐”“有什么课程”“有哪些班”“有什么适合我的”“我该选哪个”“推荐一个课程”“我想学习 AI”“怎么报名学习”等直接进入业务流程。

没有具体约束时，展示当前身份资料域的全部结构化班型卡片，并引导选择或补充条件；已有有效约束时进入现有推荐规则。卡片继续由结构化产品数据生成，推荐理由和说明继续由 composer 按 `decisionTrace` 动态生成并通过 grounding。不得按关键词直接返回固定完整正文。

未确认身份但包含通用课程信号时，返回身份澄清，不得判为 `unrelated`。

## 7. 教师枚举外城市

教师线下开课城市的唯一事实来源仍是素材 B 的结构化教师产品：北京、上海、广州。深圳、成都、杭州及其他枚举外城市走同一个通用分支，不单独硬编码城市。

规则行为：

1. 保存并确认教师所在城市，不重复询问城市。
2. 说明 L1 周末研修班上午为腾讯会议线上课程，下午为指定城市线下工作坊。
3. 询问是否可前往北京、上海或广州。
4. 可以前往时，再结合连续脱岗、等级和日期进入现有推荐。
5. 明确均不便前往时，说明资料范围内没有完全线上教师班型。
6. 可以列出最接近的结构化方案，但必须明确出行或线下条件未满足，不能声称完全匹配。

为表达该边界，只增加教师跨城可行性这一必要约束和对应规则状态；不改变教师产品事实、价格或推荐等级逻辑。

## 8. Composer 与 Grounding

composer 只接收当前身份域的候选实体、实际使用事实、计算结果、`decisionTrace`、必要动作和最短最近上下文。不得发送其他身份域的完整知识或无关完整历史。

所有现有 grounding 保留。首稿通过立即返回；只有首稿未通过且错误可重试时才生成第二稿。记录每次失败原因码和重试次数。如果诊断显示金额、日期、地区或推荐理由校验存在归一化假阳性，只修复相应归一化，不取消校验。

正常推荐最多一次 classifier 和一次成功 composer；明确信息充分、pending 可由代码填充或身份已确定且无域外证据时不调用 classifier。学校采购确定性路径保持零外部模型调用，域外路径不调用业务 composer。
