## 4. 阶段设计

### 4.1 公开前安全审计

安全审计分为当前文件、Git 索引和完整 Git 历史三层。扫描只报告文件路径、提交号和命中规则类型，不显示匹配内容或疑似凭据值。

检查范围包括：

- API Key、Bearer Token、私钥、证书及其他高置信凭据形态
- `.env*`、请求头、供应商响应、模型配置值
- Word、视频、录屏、原始素材、日志、临时文件
- 本机绝对路径和不适合公开的个人信息
- 超大文件及不必要二进制文件

`.gitignore` 至少覆盖 `.env*`（保留 `.env.example`）、`*.docx`、`*.mp4`、`录屏/`、`素材/`、`临时文件/`，并保留现有英文同类目录规则。只调整忽略策略，不删除仓库外 Word、视频或历史证据，也不误删已提交的脱敏 TASK-06 证据。

如当前文件或完整历史发现真实密钥，立即停止，不创建或公开仓库。

发布前重新确认：

- 浏览器当前登录用户为 `DingyiHuang`

Codex 的 GitHub 连接当前指向另一个账号，不能用该连接代表 `DingyiHuang` 执行发布；GitHub 创建与授权只能使用已经核实的 `DingyiHuang` 浏览器或桌面会话。如果出现重新登录、网页授权或归属不明，按任务要求停在人工检查点。

### 4.3 Vercel 部署

Vercel 连接上述公开仓库并以 `main` 部署 Production。部署前从代码中核实实际环境变量名称，预期至少为：

- `LLM_BASE_URL`
- `LLM_API_KEY`
- `LLM_MODEL`
- `LLM_TIMEOUT_MS`

只检查变量名称及 Production 是否已配置，不读取、复制或输出值。若缺少变量，参赛人需在 Vercel 控制台自行填写；不会要求把值发到对话中。

函数时长必须覆盖真实模型链路。TASK-06 记录的单次场景曾超过 40 秒，最长记录超过 60 秒。只有在当前 Vercel 账户明确显示支持值、且 Next.js 16.2.11 随附文档确认配置方式后，才允许调整 `maxDuration`；不得根据记忆猜测套餐上限。如账户上限不足，立即停止并报告。

部署成功后保存稳定 HTTPS Production 地址，验证首页和主要 JavaScript 资源均为 HTTP 200。普通 URL 不显示测试控件，`/?test=1` 保留一次性故障注入与重试功能。

### 4.4 生产冒烟

所有验收只使用 Vercel Production 地址，不以 localhost 代替。逐项记录时间、HTTP 状态、实际结果、结论和大致耗时：

1. “我想学AI”先澄清身份。
2. 学生/家长、北京、第一期、线下只推荐 `camp-p1-bj`，费用 6980 元。
3. 零基础教师且工作日不能脱岗，只推荐 L1 周末研修班。
4. 学校采购 20 人教师培训只出现“20 人起、5 万元起”，不出现 2980。
5. 天气或 Git/部署指令只返回咨询范围提示，不重复旧课程卡片。
6. 普通页面不显示测试控件。
7. `/?test=1` 完成一次模拟失败和重试恢复。
8. 完成真实对话并导出 Markdown，核对页面与文件一致。
9. 未登录/无痕访问不要求登录。
10. 首页和主要静态资源返回 HTTP 200。

任一核心场景出现业务错误、HTTP 500、函数超时、环境变量错误或来源校验错误时，停止封装，先报告根因和最小修复方案。

### 4.7 提交与标签

为解决“PDF 必须记录实际提交号”与“提交内容会改变自身哈希”的循环，采用可审计的两级交付提交：

1. 源码、README、Markdown 文档、部署配置和生产证据完成后，提交 `chore: prepare public production delivery`。交付索引记录这一实际“交付内容源提交号”。
2. 由该提交生成并验证 PDF/ZIP，再以独立封装提交加入产物。
3. `v1.0.0` 标签指向最终封装提交。

设计记录本身使用独立提交，便于在实施前审阅，不修改或重写 TASK-06 历史。不得 amend、reset、rebase 或覆盖既有提交。

最终推送后再次验证 Public 仓库和 Production；不创建 GitHub Release。
