# 技术说明

## 架构原则

项目使用 Next.js App Router、TypeScript 和服务端 Serverless 接口。核心设计是把确定性决策与语言表达分离：代码负责资料域路由、班型筛选、日期冲突、费用和优惠计算、前置条件、状态流转、异常拦截与来源拼接；LLM只负责基于已确认结构化事实生成面向用户的正文和推荐理由。不得用关键词直接返回整段固定课程答案。

知识层采用 `Camp`、`TeacherProduct`、`PlatformService` 等类型化实体。字段级来源映射生成事实编号，模型只返回本次使用的 `usedFactIds`，程序校验后统一追加资料名称和章节，避免模型编造引用。业务日期统一转为 `Asia/Shanghai` 后比较，并支持固定时间注入。费用和推荐结果由规则层输出，composer温度计划设为约0.6以保留措辞变化；classifier温度为0以提高稳定性。

模型配置只存在于服务端环境变量 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_TIMEOUT_MS`。真实密钥不进入前端、仓库、日志、文档或对话导出。`.gitignore`还排除原始Word、素材目录和录屏文件，最终公开仓库只包含二次加工的结构化运行数据。

## 确定性规则层

TASK-03在`src/lib/rules`建立纯TypeScript业务层，不依赖网络或模型：

- `status.ts`分别计算报名截止和早鸟截止，截止当日仍为有效，并在比较前校验`YYYY-MM-DD`业务日期。教师早鸟“开课日前14日”的口径统一解释为“截止日＝开课日－14个自然日”，截止当日24:00前仍有效；例如8月1日开课对应7月18日截止。
- `feeCalculator.ts`计算学生和教师费用。学生团报资格读取`Camp.groupMinimum`、`groupDiscount`、`groupScope`，由调用方传入是否满足同一期同一班型；早鸟与团报只采用优惠额较大的一项。食宿仅允许线下班并在优惠后加价。
- `studentRecommendation.ts`根据地域、营期、出行、形式和回放需求筛选真实组合，最多返回2项；不足两个有效约束时继续询问，用户拒绝或连续两轮无新增约束时返回可退出的资料不足状态。广州家长首次要求本地线下时返回`boundary_follow_up`并追问`canTravel`，不能出行后才转线上，能出行则继续确认北京或上海目的地。
- `teacherRecommendation.ts`把明确目标或起始能力映射到L1、L2、L3，把连续时间映射为集训、不能脱岗映射为周末。“零基础”使用已采集的`startingLevel=beginner`映射L1，不虚构学习目标。未说明时间形式时不会默认集训；L2/L3前置未满足时返回阻断和下一步，前置未知时先询问。
- `institutionRouting.ts`仅返回素材C的机构服务并标记不进入个人推荐；`boundaries.ts`把教师退款未提供、会员价格未提供建模为结构化边界。

推荐项携带`decisionTrace`，每一项包含规则代码、参与判断的用户约束键和实际使用的事实编号。所有`constraintKeys`在进入composer前必须是本轮已采集键的子集；带`nextQuestionKeys`的结果优先进入追问路由，不能只按状态生成终止回答。费用决策也记录报名、早鸟和优惠分支。`src/lib/citations`只根据这些事实编号读取字段来源表，按资料、章节和小节去重；它不生成课程正文，也不允许模型提供章节号。

## 服务端模型适配与实测结论

TASK-04建立了可替换的OpenAI兼容服务端适配层。`src/lib/llm/runtime.ts`使用`server-only`保护，只在请求运行时读取已命名的环境变量；前端只能请求`POST /api/chat`，不能获得模型地址、模型名或密钥。客户端统一处理超时、HTTP错误、响应信封和文本提取，不记录请求头、密钥或完整敏感配置。

2026-07-22重新执行真实模型闸门，脱敏模型名为`deepseek-v4-flash`：普通中文请求HTTP 200，端到端耗时246ms；启用`response_format: { type: "json_object" }`的严格JSON请求HTTP 200，耗时851ms，响应无Markdown代码块或前后缀，可直接`JSON.parse`。两次均显著低于`LLM_TIMEOUT_MS=20000`，因此本阶段保留20秒超时；供应商当前兼容`response_format`/JSON mode。若供应商以后取消兼容，系统会把非法JSON作为模型错误处理并最多重试一次，不会用字符串截取或代码块清洗伪装成严格结构化输出。

classifier固定使用`temperature=0`和JSON mode，只返回身份、意图、资料主题、实体指代及约束候选。程序要求每个候选都能在本次用户原文找到证据，再决定是否更新会话；“零基础”落为`startingLevel=beginner`，不能用同一段证据虚构`goal`。composer使用`temperature=0.6`和JSON mode，只接收已确认事实、程序计算结果、`decisionTrace`、允许动作及最多9条短上下文。它负责动态生成正文和理由，但不得生成素材名或章节；程序根据经过白名单校验的`usedFactIds`追加完整来源尾注。

## 会话接口与状态合同

`POST /api/chat`接收以下字段：`message`、上一次返回的`state`、可选`action`和测试模式标记。`action`支持`message`、`reset`、`menu`和`inject_next_failure`；最后一项只有`testMode=true`时才生效，供TASK-05的`?test=1`界面注入“下一次模型失败”，不会调用真实模型。响应包含`status`、最终正文`message`、新`state`、程序收集的`sources`、相关`entityIds`、允许的`actions`，失败时另含脱敏的`error.code`与`retryable`。

服务端状态保存当前资料域、学生/教师约束、机构需求、当前班型、最近推荐、待追问键与选项、短上下文以及单次测试故障标志。所有传入状态都先清洗；重置或返回菜单会清空身份、约束、班型和历史。跨域请求会明确提示并清除旧域的班型指代。推荐后只有唯一候选时才继承“这个班”；有两个候选时继续追问选择，不擅自绑定其中一个。

生成前依次执行以下保护：带`nextQuestionKeys`的计划无条件优先走追问路由；每个`decisionTrace[].constraintKeys`必须是本次会话已采集键的子集；`usedFactIds`必须来自本次计划提供的事实，且每条含事实的推荐轨迹至少使用一个对应事实；composer不得输出来源标记或新增动作；金额与日期必须来自已确认事实、用户原文或程序计算。普通序号和数量表达（如“第5天”“1—2个班型”）不参与高风险拦截。

广州学生线下边界由规则层先返回`boundary_follow_up`。程序固定追加“素材A没有广州学生线下班。”这一事实边界，再要求composer询问能否去北京、上海或均不便出行；只有用户明确均不便出行后才允许推荐线上。这里的固定前缀属于资料边界声明，不是固定课程答案，课程说明和推荐理由仍由composer动态生成。

模型超时、5xx、限流、非法JSON或生成校验失败最多重试一次。两次仍失败时返回可重试错误并原样保留调用前状态；配置错误和401/402/403等不可重试错误不会盲目重试，也绝不回退到固定课程答案冒充模型结果。

## 当前实现状态

项目当前包含9个学生营期/班型组合、6个教师产品和7项平台服务。业务日期统一使用`Asia/Shanghai`，支持固定时钟且UTC跨日边界测试继续通过。参赛人亲自提供的人工知识金标59项断言，以及规则层7个费用结果、10个状态结果，均作为独立预期参与测试。

截至TASK-04，服务端模型适配、classifier、composer、会话状态机、事实计划、来源尾注、高风险校验、失败重试和测试故障注入均已实现。全量Vitest为13个测试文件、74条测试，无失败、无跳过、无TODO；TypeScript类型检查、ESLint和生产构建均通过。用户界面、对话导出和`?test=1`测试控件仍属于TASK-05，本阶段未实现。
