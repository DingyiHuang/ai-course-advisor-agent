# 技术说明

## 架构原则

项目使用 Next.js App Router、TypeScript 和服务端 Serverless 接口。核心设计是把确定性决策与语言表达分离：代码负责资料域路由、班型筛选、日期冲突、费用和优惠计算、前置条件、状态流转、异常拦截与来源拼接；LLM只负责基于已确认结构化事实生成面向用户的正文和推荐理由。不得用关键词直接返回整段固定课程答案。

知识层采用 `Camp`、`TeacherProduct`、`PlatformService` 等类型化实体。字段级来源映射生成事实编号，模型只返回本次使用的 `usedFactIds`，程序校验后统一追加资料名称和章节，避免模型编造引用。业务日期统一转为 `Asia/Shanghai` 后比较，并支持固定时间注入。费用和推荐结果由规则层输出，composer温度计划设为约0.6以保留措辞变化；classifier温度为0以提高稳定性。

模型配置只存在于服务端环境变量 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_TIMEOUT_MS`。真实密钥不进入前端、仓库、日志、文档或对话导出。`.gitignore`还排除原始Word、素材目录和录屏文件，最终公开仓库只包含二次加工的结构化运行数据。

## 确定性规则层

TASK-03在`src/lib/rules`建立纯TypeScript业务层，不依赖网络或模型：

- `status.ts`分别计算报名截止和早鸟截止，截止当日仍为有效，并在比较前校验`YYYY-MM-DD`业务日期。教师早鸟“开课日前14日”的口径统一解释为“截止日＝开课日－14个自然日”，截止当日24:00前仍有效；例如8月1日开课对应7月18日截止。
- `feeCalculator.ts`计算学生和教师费用。学生团报资格读取`Camp.groupMinimum`、`groupDiscount`、`groupScope`，由调用方传入是否满足同一期同一班型；早鸟与团报只采用优惠额较大的一项。食宿仅允许线下班并在优惠后加价。
- `studentRecommendation.ts`根据地域、营期、出行、形式和回放需求筛选真实组合，最多返回2项；不足两个有效约束时继续询问，用户拒绝或连续两轮无新增约束时返回可退出的资料不足状态。广州家长首次要求本地线下时返回`boundary_follow_up`并追问`canTravel`，不能出行后才转线上，能出行则继续确认北京或上海目的地。
- `teacherRecommendation.ts`把明确目标或起始能力映射到L1、L2、L3，把连续时间映射为集训、不能脱岗映射为周末。“零基础”使用已采集的`startingLevel=beginner`映射L1，不虚构学习目标。未说明时间形式时不会默认集训；L2/L3前置未满足时返回阻断和下一步，前置未知时先询问。
- `institutionRouting.ts`仅返回素材C的机构服务并标记不进入个人推荐；`boundaries.ts`把教师退款未提供、会员价格未提供建模为结构化边界。

推荐项携带`decisionTrace`，每一项包含规则代码、参与判断的用户约束键和实际使用的事实编号。所有`constraintKeys`在进入composer前必须是本轮已采集键的子集；带`nextQuestionKeys`的结果优先进入追问路由，不能只按状态生成终止回答。费用决策也记录报名、早鸟和优惠分支。`src/lib/citations`只根据这些事实编号读取字段来源表，按资料、章节和小节去重；它不生成课程正文，也不允许模型提供章节号。

## 服务端模型适配与实测结论

TASK-04建立了可替换的OpenAI兼容服务端适配层。`src/lib/llm/runtime.ts`使用`server-only`保护，只在请求运行时读取已命名的环境变量；前端只能请求`POST /api/chat`，不能获得模型地址、模型名或密钥。客户端统一处理超时、HTTP错误、响应信封和文本提取，不记录请求头、密钥或完整敏感配置。

2026-07-22重新执行真实模型闸门，脱敏模型名为`deepseek-v4-flash`：普通中文请求HTTP 200，端到端耗时246ms；启用`response_format: { type: "json_object" }`的严格JSON请求HTTP 200，耗时851ms，响应无Markdown代码块或前后缀，可直接`JSON.parse`。两次均显著低于`LLM_TIMEOUT_MS=20000`，因此本阶段保留20秒超时；供应商当前兼容`response_format`/JSON mode。若供应商以后取消兼容，系统会把非法JSON作为模型错误处理并最多重试一次，不会用字符串截取或代码块清洗伪装成严格结构化输出。

classifier固定使用`temperature=0`和JSON mode，只返回身份、意图、资料主题、实体指代及约束候选。程序要求每个候选都能在本次用户原文找到证据，再决定是否更新会话；“零基础”落为`startingLevel=beginner`，不能用同一段证据虚构`goal`。composer使用`temperature=0.6`和JSON mode，只接收已确认事实、程序计算结果、`decisionTrace`、允许动作及最多9条短上下文。它负责动态生成正文和理由，但不得生成素材名或章节；程序根据经过白名单校验的`usedFactIds`追加完整来源尾注。

## 会话接口与状态合同

`POST /api/chat`接收以下字段：`message`、上一次返回的`state`、可选`action`和测试模式标记。`action`支持`message`、`reset`、`menu`、`catalog`、`select_domain`、`select_entity`和`inject_next_failure`。显式身份和班型选择由代码校验，不需要解析AI正文；`catalog`由程序准备当前资料域的全部事实后仍交给composer动态组织；最后一项只有`testMode=true`时才可设置一次故障。响应包含`status`、最终正文`message`、新`state`、程序收集的`sources`、相关`entityIds`、允许的`actions`、结构化`presentation`和程序生成的`notices`；边界流程另返回`boundaryCode`，失败时另含脱敏的`error.code`与`retryable`。

服务端状态保存当前资料域、学生/教师约束、机构需求、当前班型、最近推荐、待追问键与选项、短上下文以及单次测试故障标志。所有传入状态都先清洗；重置或返回菜单会清空身份、约束、班型和历史。跨域切换作为一次原子状态转换：保留对话历史，先清空学生/教师约束、机构服务分类、当前实体、最近推荐和待追问，再从本条消息采集新域约束。API以`identity_switched`通知返回切换前后域和可见系统文案，前端单独显示系统消息。推荐后只有唯一候选时才继承“这个班”；有两个候选时继续追问选择，不擅自绑定其中一个。

TASK-05失败项修复在`src/lib/conversation/routing.ts`增加保守的确定性路由层，顺序固定为：明确机构服务语境、明确第一人称个人身份、当前待追问的规范回答或当前实体事实问法、LLM classifier、无关问题兜底。机构采购信号优先于“教师”等个人身份词；孤立“学校”不会触发切换。“均不便出行”等规范回答在classifier之前映射到`canTravel=false`，时间、费用、地点、准备事项和报名等当前实体问法映射为`factTopics`。该层只决定身份、状态字段和操作类型，不返回课程正文，正文仍由composer动态生成。

生成前依次执行以下保护：带`nextQuestionKeys`的计划无条件优先走追问路由；每个`decisionTrace[].constraintKeys`必须是本次会话已采集键的子集；`usedFactIds`必须来自本次计划提供的事实，且每条含事实的推荐轨迹至少使用一个对应事实；composer不得输出来源标记或新增动作；金额与日期必须来自已确认事实、用户原文或程序计算。推荐路由还要求composer按每个真实`entityId`返回`recommendationReasons`，每个已参与决策的约束键恰好一条，不能缺失、重复或引入新约束。理由也参与来源禁写和高风险金额/日期校验。

金额校验使用`src/lib/validation/money.ts`的受控归一化：只识别带`元`、`千元`、`万元`或人民币符号的金额语境，支持`5万元`、`五万元`、`1万—3万元`和`500—1500元/人`等表达并转换为基础元值。允许金额只从价格/费用字段、程序计算、明确金额文本和用户原文收集；`minimumPeople`、回放天数、课程日序等普通数字不再被当作金额。日期校验仍只识别ISO日期、月日和明确月日范围，不扩展为数字白名单。因此“20人起”“第5天”“30天回放”“1—2个班型”放行，未授权“2万元起”仍被拒绝。

广州学生线下边界由规则层先返回`boundary_follow_up`。程序固定追加“素材A没有广州学生线下班。”这一事实边界，再要求composer询问能否去北京、上海或均不便出行；只有用户明确均不便出行后才允许推荐线上。这里的固定前缀属于资料边界声明，不是固定课程答案，课程说明和推荐理由仍由composer动态生成。

模型超时、5xx、限流、非法JSON或生成校验失败最多重试一次。两次仍失败时返回可重试错误并原样保留调用前状态；配置错误和401/402/403等不可重试错误不会盲目重试，也绝不回退到固定课程答案冒充模型结果。测试故障存放在会话状态的`test.failNextModelCall`，消费一次后先清除再返回模拟失败，因此前端用失败响应中的新状态重试时会恢复正常模型调用。

## TASK-05界面、推荐展示与导出

`src/components/CourseAdvisor.tsx`是交互边界，负责页面消息、输入校验、加载状态、结构化动作、重试快照、测试模式显示和浏览器下载；它不包含课程知识或模型配置。`src/app/page.tsx`在服务端读取`searchParams`，只把`test=1`布尔值传给客户端组件，因此普通URL不会先渲染再闪现测试按钮。CSS Module实现桌面双栏和手机单列布局，用户、AI、系统与错误使用独立语义样式。

`src/lib/conversation/presentation.ts`把已确定的知识实体、费用计算、LLM动态理由和程序来源组合为`RecommendationCard`或`InstitutionServiceCard`。产品名称、日期、地点、标准价和实际价来自代码；推荐理由来自composer，约束标签和值来自当前已清洗状态；卡片来源只保留该实体实际使用的事实。程序固定显示“资料未提供实时余位”，不会把`capacity`或`minimumToOpen`当作剩余名额。机构服务卡只读取`PlatformService`，不会加载学生或教师个人价格。

前端不扫描AI正文决定按钮。`pendingQuestionOptions`直接渲染为回答选项，`actions`按服务端允许的精确动作名映射；“继续咨询该班”调用`select_entity`并且服务端只接受`lastRecommendationIds`中的实体。“查看全部课程”调用`catalog`，不会依赖“全部课程”等关键词分类。

每条错误消息保存自己的原请求快照，包含`message`、`state`、`action`和`errorMessageId`；错误卡的“重试原请求”只读取该卡快照，不再依赖全局最后一次错误。重试不重复添加用户气泡或推荐卡，强制`testMode=false`；服务器错误响应的`state`覆盖请求快照，保证一次性模拟故障已清除而其他会话状态保留。空输入和超过500字在`fetch`前拦截；网络异常只生成本地脱敏错误卡。

`src/lib/export/markdown.ts`是纯数据导出模块。它从当前实际消息、`ConversationState`、结构化推荐和来源生成Markdown，并用`Intl.DateTimeFormat`显式指定`Asia/Shanghai`。实际对话保持完整；“推荐结果”只汇总当前身份资料域的卡片，并按canonical entity ID去重，同一产品多次回答只保留一条。来源区保留完整会话实际使用来源并明确标注“完整会话历史”。文件包含测试编号、身份、约束、当前班型/机构分类、实际对话、推荐、来源、测试模式和实际错误；没有消息时明确输出“尚无”，不构造示例对话。浏览器下载文件名带会话编号和上海时间，单元测试使用固定时间验证内容与文件名。

## 日期、费用和职责边界复述

教师早鸟“开课日前14日”的业务定义固定为“截止日＝开课日－14个自然日，截止当日24:00前有效”。例如8月1日开课对应7月18日截止。Serverless运行时的UTC时间不能直接参与判断，必须先转换为`Asia/Shanghai`业务日期并按`currentDate <= deadline`比较。

代码负责身份显式动作、约束清洗、资料域、筛选、日期、费用、优惠、前置条件、推荐映射、会话状态、异常拦截和来源追加。classifier只提取带用户原文证据的候选；composer只根据本次事实、计算和决策轨迹动态生成正文与推荐理由。页面只展示结构化响应。三层均不得用关键词直接返回整段固定课程答案。
