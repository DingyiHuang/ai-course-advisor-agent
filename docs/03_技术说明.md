# 技术说明

## 架构原则

项目使用 Next.js App Router、TypeScript 和服务端 Serverless 接口。核心设计是把确定性决策与语言表达分离：代码负责资料域路由、班型筛选、日期冲突、费用和优惠计算、前置条件、状态流转、异常拦截与来源拼接；LLM只负责基于已确认结构化事实生成面向用户的正文和推荐理由。不得用关键词直接返回整段固定课程答案。

知识层采用 `Camp`、`TeacherProduct`、`PlatformService` 等类型化实体。字段级来源映射生成事实编号，模型只返回本次使用的 `usedFactIds`，程序校验后统一追加资料名称和章节，避免模型编造引用。业务日期统一转为 `Asia/Shanghai` 后比较，并支持固定时间注入。费用和推荐结果由规则层输出，composer温度计划设为约0.6以保留措辞变化；classifier温度为0以提高稳定性。

模型配置只存在于服务端环境变量 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_TIMEOUT_MS`。真实密钥不进入前端、仓库、日志、文档或对话导出。`.gitignore`还排除原始Word、素材目录和录屏文件，最终公开仓库只包含二次加工的结构化运行数据。

TASK-02已在 Next.js 16、React 19、TypeScript、ESLint 和 Vitest 环境中建立类型化知识层。知识清单包含9个学生营期/班型组合、6个教师产品和7项平台服务，Camp团报门槛、优惠额和适用范围均为实体字段，不写死在费用函数中。字段来源映射可以从`${entityId}.${field}`事实编号取得资料和章节；课程规模与最低开班人数独立保存，`availabilityKnown`固定为`false`。

业务日期由`src/lib/time/shanghai.ts`统一转换为`Asia/Shanghai`日期，支持注入固定时钟，并验证UTC 16:00跨日边界。参赛人亲自提供的人工金标已接入独立测试，54项断言全部通过。推荐、费用、会话和模型适配仍按任务卡留到后续阶段；TASK-03的12条日期及费用用例目前明确标记为TODO。
